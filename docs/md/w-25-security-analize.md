# Анализ безопасности кода для Express-JS-Pet

## Проведение анализа

**Чек-лист безопасности:**

- Используется ли HTTPS?
    - Да, сервис деплоя автоматически настраивает SSL-сертификаты.
- Пароли хранятся в зашифрованном (хешированном) виде?
    - Да, используется bcrypt для хеширования паролей.
- Есть ли защита от SQL-инъекций?
    - Используется MongoDB (NoSQL), но возможны NoSQL-инъекции при некорректной обработке данных.
- Проверяется ли авторизация при доступе к данным?
    - Для создания, редактирования и удаления постов требуется JWT-токен, но нет проверки, что пользователь редактирует только свои посты (актуальный баг).
- Защищены ли данные пользователя от подмены?
    - Не полностью: нет проверки, что пользователь может изменять только свои посты.

## Документируем уязвимости

| Уязвимость                        | Где обнаружена (файл, строка)         | Решение/рекомендация                                  |
|------------------------------------|---------------------------------------|-------------------------------------------------------|
| Нет проверки владельца поста при редактировании/удалении | `src/controllers/PostController.js`   | Добавить проверку: редактировать/удалять может только автор поста |
| Нет HTTPS                          | Внешняя инфраструктура                | Запускать за обратным прокси с SSL                    |
| Возможна NoSQL-инъекция            | Все места, где используются параметры из запроса | Использовать валидацию и sanitize входных данных      |
| JWT секрет хранится в .env         | `.env`                                | Не выкладывать .env в публичный доступ                |
| Нет ограничения размера загружаемых файлов | `index.js` (роут /upload)            | Добавить ограничение размера и типа файла              |
